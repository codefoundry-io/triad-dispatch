# Cross-family review — failure-mode index

Loaded on demand from `triad-cross-family-review/SKILL.md`. This is a
symptom → cause → rule lookup, not a second statement of the rules: each Fix
cell names the rule (or reference) that owns the behaviour. Open it when a round
misbehaves and you want to know which rule already covers it.

| Symptom | Cause | Where the fix lives |
|---|---|---|
| Reviewers all pass a leader blind-spot | claude leg was leader-inline, or a suspect was framed as fact | rules 1-2 |
| claude leg keeps returning SAFE while codex/agy escalate residuals | claude prompt under-reasoned / not adversarial / shallow tier | rule 10 (max-thinking + adversarial + no severity-deflation); rule 1 for the tier |
| A vendor leg returns a fast bare SAFE/none despite a deep tier | Tier was set but the leg got no adversarial framing — it rubber-stamped | rule 11 (framing, and the latency threshold); an agy pass is advisory regardless, rule 1 |
| agy leg's `read_audit.digest.files_read` never lists a packet file's path | The agy HARNESS wandered outside the packet dir, or never opened it, before answering | `references/leg-contracts.md` § agy read-audit gate — it owns the VOID / INCONCLUSIVE branch and the re-dispatch rule |
| Merged on 2-of-3 SAFE | Averaged instead of consolidated | rule 4 |
| First-pass fixes assumed sufficient | No re-confirm | rule 5 |
| Vendor leg times out with no verdict | Reviewer live-ran the code → hung on a real vendor call, sandbox couldn't reap it | rule 7 (no-exec directive AND a scaled timeout) |
| A leg returns a repair-routed wrapper failure (`unknown` / `extraction-error` / `timeout`) | The leg's CLI transport hiccuped — not a review verdict | Let that leg's dispatch SKILL run its repair path, then re-dispatch the leg once; if it fails again the family is missing this round (rules 13 + 1). A wrapper failure is never counted as SAFE |
| agy leg returns `admission-refused` (65) — `tool(s) outside the allowlist appeared in the stream: ["manage_task"]` (or `send_message`, `run_command`), verdict 0 bytes | agy advertised its full tool registry and the model used a planner / subagent / shell tool; the prompt or agent body did not name the five permitted tools (fixed 0.29.1 — if it recurs, check the host ran `--setup-agents` and the rendered prompt carries the TOOL ALLOWLIST block) | `references/leg-contracts.md` § agy leg — one retry, then terminally missing; consolidate the other legs regardless |
| agy leg returns `vendor-timeout` (65) — `result.error` "timeout waiting for response", 0-byte verdict after ~850 s | the vendor's own turn budget ran out while the leg was still reading (wide repo reads on a broad packet) | `references/leg-contracts.md` § agy leg — re-dispatch once with a narrower read scope, then terminally missing |
| agy leg returns `truncated-answer` (65) with no verdict | The verdict folded CLI-side; widening the sandbox to let it write would forfeit rule-7 containment on the untrusted-input leg | `references/leg-contracts.md` § agy leg, "Folded verdict" — it owns the one re-dispatch and the never-widen rule |
| agy/gemini leg times out / extraction-error with no verdict on a LARGE review | The leg was told to self-assemble a large diff/packet and ran out its wall-time budget stitching it | rule 8 (pre-assemble one focused file); codex gets the same subset inlined, rule 9 |
| codex leg returns no verdict / "couldn't access the files" / reviews the literal string `$(cat ...)` | codex was handed a file PATH under read-only+no-exec, or `$(cat ...)` sat in a single-quoted heredoc (literal, unexpanded) | rule 9 and `references/leg-contracts.md` § codex leg |
| codex leg times out at max tier on a big inline packet | Timeout not scaled to packet × tier | Shrink to the focused subset first (rules 8-9); if the packet must stay large, raise the timeout per rule 7 |
| Rounds keep flipping each other's verdicts / re-litigating settled points | The loop stopped converging — more rounds only oscillate | rule 12 (stop; conflict table to the owner) |
| Leader burns the wait busy-polling legs, or picks up unrelated work mid-review | Poll loops / context interleaving instead of event-driven waits | rule 13 |
| Codebase grows guards/fallbacks each round; leader lands new defensive layers mid-round without sign-off | The loop rewards adding code; speculative findings entered the fix queue as must-fix | rule 14 and `references/triage.md` |
| Every leg holding ANY finding — Minor-only included — returns MERGE WITH FIXES; literal unanimous SAFE never arrives | Leg prompts lacked the verdict-selection rule (verdict must track the BLOCKING axis; the schema explicitly permits SAFE + Minor/HARDENING-SUGGESTION) | `references/triage.md` § Reviewer-side instruction (Verdict selection); the `prepare` templates carry it; Flow 4's non-blocking-MWF carve-out releases the gate meanwhile |
| A plan/gate document that records its own review keeps sprouting non-blocking prose-tail findings round after round | Self-recording target: folds add text, fix sentences become review surface, self-referential records lag a round | `references/triage.md` § Loop exit (self-recording targets — mechanical census at implementation time + non-blocking close) |
| agy leg returns `admission-refused` (65) after ONE stray tool call — a paging OVERSHOOT, a does-not-exist open, or a single forbidden call — on a packet ≳ 75 KB | A big packet drives wide reads, and every extra step is another chance at an errored/denied one (turn-terminal since agy 1.1.15) | `references/leg-contracts.md` § agy leg — ONE retry on the IDENTICAL prompt; prefer a SMALLER packet next round (a plan gate embeds the artifact under review only and leaves READMEs to the read grant) |
| agy (or any wrapper) leg returns `schema-fail` (66) naming `file must be a repo-relative path` | The leg reported findings with an ABSOLUTE `file` — typically the absolute packet path (observed 2026-09-05, P6 gate r3 attempt 1: 6 errors; the r2 quarantined answer did the same) | Fixed in CFR 0.29.2 — the rendered prompts carry the REPO-RELATIVE pin sentence. One retry of the leg; if it recurs on a 0.29.2-rendered prompt that is a NEW defect, not a retry case |
| A leg "never launched" — no run-log, no verdict, no stderr | Its dispatch was CHAINED (`&&`) behind a manual file operation on a helper-managed file, and the file op failed first (observed 2026-09-05, P6 gate r2 codex) | `references/packet-lifecycle.md` § Round integrity — never chain a file op before a dispatch; the helper owns the packet dir, so no hand-move is needed at all |
| An X leg (`x-<name>`) fails, times out, or returns an unusable verdict | An experimental leg exercises an unproven vendor / model / effort — measuring that is the point of the campaign | SKILL.md rule 15 — an X leg is ADVISORY and NEVER blocks or delays the round: record the failure in the comparison record (`references/triage.md` § X-leg comparison record) and consolidate the three families as usual |
| An X leg's verdict is refused at admission with a review ID mismatch | The leg echoed the packet's `Review metadata:` id (the STANDING round id, inside the digest and unforkable) instead of its own `<review-id>.<x-name>` binding value | The X renders carry a disambiguation sentence since CFR 0.29.2; if it still happens, ONE targeted re-ask of that leg for a corrected `review_id` — never a leader edit of the verdict file (`references/triage.md` § X-leg comparison record; SKILL.md rule 15) |
| verify fails "round evidence changed" on `agy-read-audit.json` with an unmutated tree | The round-invariant leg output was censused at capture and rewritten by the round's dispatch | `references/packet-lifecycle.md` § Round integrity — `prepare`/`capture` auto-preserve it since 2026-08-11 |
