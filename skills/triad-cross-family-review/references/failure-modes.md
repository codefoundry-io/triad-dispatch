# Cross-family review — failure-mode index

Loaded on demand from `triad-cross-family-review/SKILL.md`. This is a
symptom → cause → rule lookup, not a second statement of the rules: each Fix
cell names the rule (or reference) that owns the behaviour. Open it when a round
misbehaves and you want to know which rule already covers it.

| Symptom | Cause | Where the fix lives |
|---|---|---|
| Reviewers all pass a leader blind-spot | claude leg was leader-inline, or a suspect was framed as fact | rules 1-2 |
| claude leg returns SAFE while codex/agy return a must-fix | Different legs found different things — not a vote to average | rule 4: verify the must-fix against the current bytes; a verified defect is fixed and the next round re-reviews everything (rule 5). The leader adds no persona or intensity request to the claude prompt (rule 10); its depth is the preset's frontmatter effort (rules 1, 15) |
| A vendor leg returns a fast, terse SAFE despite a deep tier | A shallow pass is possible; the result is still valid | rule 11: a valid SAFE is never retried (R-RETRY); another round over it needs new evidence (rule 5). For the agy entry rule 1's mechanical read-audit gate decides first, and an ungated answer is UNVERIFIED (invalid), not merely discounted; latency is a signal to record (`references/evidence.md`) |
| agy leg's `read_audit.digest.files_read` never lists a packet file's path | The agy HARNESS wandered outside the packet dir, or never opened it, before answering | `references/leg-contracts.md` § agy read-audit gate — it owns the VOID / INCONCLUSIVE branch and the re-dispatch rule. On a v2 round a `retry` clears this VOID only while the read-blind attempt's census is readable and id-bearing; when it is missing or incomplete the hook load check refuses and only a NEW round clears it |
| Merged on 2-of-3 SAFE | Averaged instead of consolidated | rule 4 |
| First-pass fixes assumed sufficient | No new round over the fixed bytes | rule 5 (every selected entry reviews the new basis in full) |
| Vendor leg times out with no verdict | Reviewer live-ran the code → hung on a real vendor call, sandbox couldn't reap it | rule 7 (no-exec directive AND the generous `timeout_s` 3600) |
| A leg returns a repair-routed wrapper failure (`unknown` / `extraction-error` / `timeout`) | The leg's CLI transport hiccuped — not a review verdict | Let that leg's dispatch SKILL run its repair path, then re-dispatch it ONCE as a NEW attempt — `retry` (rule 13), never a re-run into the recorded attempt (its guard refuses that); if it fails again the entry is missing this round (rules 13 + 1, `INCOMPLETE`). A wrapper failure is never counted as SAFE |
| A leg ends `[wrapper] <cli> cli-subscription-cap` (exit 65) and `collect` reports `INCOMPLETE` | That family's subscription quota is used up; a retry before the reset returns the same cap | SKILL.md Flow 4 `INCOMPLETE`: no retry before the reset, no other model, no leg added by the host; the OWNER waits, records an exception on the answering entries (the round stays `INCOMPLETE`, never agreement), or asks for a roster change (a NEW round) |
| codex leg returns `input-delivery-failed` (65) with a 0-byte verdict — its stderr carries `… but stdin delivery failed:<Class>` (or `unconfirmed`) and admission refuses the empty file | The wrapper's OWN stdin transport did not confirm delivery of the leg body to the codex child (early close / blocked writer) — a transport hiccup, not a review verdict and not a classifier gap (never a repair dispatch) | rule 13 — re-dispatch that leg ONCE on the unchanged packet as a NEW attempt (`retry`; the round tree is frozen, so the same bytes are re-sent); a second `input-delivery-failed` makes the entry terminally missing for the round; the summary line + the `stdin delivery` line go into the round record |
| agy leg returns `admission-refused` (65) — `tool(s) outside the allowlist appeared in the stream: ["manage_task"]` (or `send_message`, `run_command`), verdict 0 bytes | agy advertised its full tool registry and the model used a planner / subagent / shell tool; the prompt or agent body did not name the five permitted tools (check the host ran `--setup-agents` and the rendered prompt carries the TOOL ALLOWLIST block; a call the worktree PreToolUse hook BLOCKED is logged as `blocked-calls`, never refused — only an off-list call that EXECUTED, or errored for a non-denial reason, refuses) | `references/leg-contracts.md` § agy leg — one retry, then terminally missing; consolidate the other legs regardless |
| agy leg returns `vendor-timeout` (65) — `result.error` "timeout waiting for response", 0-byte verdict after ~850 s | the vendor's own turn budget ran out while the leg was still reading (wide repo reads on a broad packet) | `retry` re-dispatches the SAME frozen prompt and scope once (a narrower scope is a changed basis — a NEW round, R-RETRY / R-REREVIEW); if it times out again the entry is missing (`INCOMPLETE`) (`references/leg-contracts.md` § agy leg) |
| agy leg returns `truncated-answer` (65) with no verdict, and the wrapper's stderr does NOT carry the reader-failure line | The verdict folded CLI-side (the other `truncated-answer` cause — a broken output READER — is its own row below); widening the sandbox to let it write would forfeit rule-7 containment on the untrusted-input leg | `references/leg-contracts.md` § agy leg, "Folded verdict" — it owns the one re-dispatch and the never-widen rule |
| agy/gemini leg times out / extraction-error with no verdict on a LARGE review | The leg was told to self-assemble a large diff/packet and ran out its wall-time budget stitching it | rule 8 (`--diff-path` / `--tests-path` / `--excerpt`); every leg reads the same worktree files, rule 9 |
| codex leg returns no verdict / "couldn't access the files" / reviews the literal string `$(cat ...)` | codex was handed a file PATH under read-only+no-exec, or `$(cat ...)` sat in a single-quoted heredoc (literal, unexpanded) | rule 9 and `references/leg-contracts.md` § codex leg |
| codex leg times out at max tier on a big inline packet | The packet outgrew even the roster's `timeout_s` 3600 | Shrink to the focused subset first (rules 8-9); raise the entry's `timeout_s` only when the packet must stay large (rule 7; a new basis) |
| Rounds keep flipping each other's verdicts / re-litigating settled points | Those items stopped converging — repeating them without new evidence only oscillates | rule 12: stop repeating each item no new evidence addresses (other items continue); only a CONFLICTED item — both findings survive verification and cannot coexist — goes to the owner, with the conflict table |
| Leader burns the wait busy-polling legs, or picks up unrelated work mid-review | Poll loops / context interleaving instead of event-driven waits | rule 13 |
| Codebase grows guards/fallbacks each round; leader lands new defensive layers mid-round without sign-off | The loop rewards adding code; speculative findings entered the fix queue as must-fix | rule 14 and `references/triage.md` |
| Every leg holding ANY finding — Minor-only included — returns MERGE WITH FIXES; literal unanimous SAFE never arrives | Leg prompts lacked the verdict-selection rule (verdict must track the BLOCKING axis; the schema explicitly permits SAFE + Minor/HARDENING-SUGGESTION) | The v2 prompts carry the shared `verdict-selection-rule` clause; a Minor-only negative is still NOT agreement — `collect` returns `BLOCKED` with that entry's deviation recorded (`references/triage.md` § Collect outcomes); only a later round in which every entry returns SAFE TO MERGE agrees (R-AGREE) |
| A plan/gate document that records its own review keeps sprouting non-blocking prose-tail findings round after round | Self-recording target: folds add text, fix sentences become review surface, self-referential records lag a round | `references/triage.md` § Loop exit (self-recording targets — mechanical census at implementation time; while the tail keeps the round non-agreed, a recorded stop reason or an owner exception, never agreement) |
| agy leg returns `admission-refused` (65) after ONE stray tool call — a paging OVERSHOOT, a does-not-exist open, or a single forbidden call — on a packet ≳ 75 KB | A big packet drives wide reads, and every extra step is another chance at an errored/denied one (turn-terminal on agy 1.1.15 and later) | `references/leg-contracts.md` § agy leg — ONE retry on the IDENTICAL prompt; prefer a SMALLER packet next round (a plan gate embeds the artifact under review only and leaves READMEs to the read grant) |
| agy (or any wrapper) leg returns `schema-fail` (66) naming `file must be a repo-relative path` | The leg reported findings with an ABSOLUTE `file` — typically the absolute packet path | The rendered prompts carry the REPO-RELATIVE pin sentence. One retry of the leg; if it recurs, that is a NEW defect, not a retry case |
| A leg answered, but the summary line's `prompt_file=<abs>` / the audit row's `prompt_file_resolved` names a DIFFERENT file than intended | The dispatch used a RELATIVE `--prompt-file` / `--cwd`. The wrapper does not refuse it (spec C28): it resolves the path MECHANICALLY against its own process-entry cwd (never the child `--cwd`), runs every pre-existing validation unchanged, and RECORDS the resolved absolute path. A reverted session cwd therefore names a same-named WRONG file silently at dispatch time — the record is what makes it legible afterwards | Read the recorded resolved path before trusting the verdict; re-dispatch on the right file. Prevention: dispatch the ABSOLUTE lines `prepare` prints, never a hand-typed relative one. `references/leg-contracts.md` § codex leg call site; root `CLAUDE.md` § Pitfalls 5 |
| A leg exits 3 within seconds, stdout EMPTY, stderr names the RESOLVED candidate (`--prompt-file 'x.txt' resolved against process cwd /… -> /…/x.txt: not a file`) | The resolved path still fails a pre-existing validation — it does not exist, is not a regular file/dir, or falls outside `TRIAD_WRAPPER_ALLOWED_ROOTS`. C28 governs WHERE a relative path resolves, not WHETHER it is validated | Fix the path the refusal names (it quotes both the text given and where it resolved), then re-dispatch |
| `collect` exits 5 `INCOMPLETE` | One or more ENABLED roster entries returned no VALID verdict — missing output file, failed admission, (on an agy route) a custody check / read-audit gate / hook LOAD CHECK that did not pass, or an entry SKIPPED at prepare, which `collect` counts and names as `missing` (`SKIPPED at prepare and never dispatched: …`). Never agreement and never a silent pass | Read the entry's reason first. A SKIPPED entry is refused by `retry` (`it never ran, so there is no attempt to retry`) — prepare a new round with that entry resolvable. Otherwise diagnose why that entry failed to RUN, then `retry <packet-dir> r<N> <name> --diagnosis "<why>"` (attempt K+1 on the unchanged basis) and dispatch the printed new attempt. A valid NEGATIVE verdict is completed work — never a retry case (SKILL rule 13; `references/triage.md` § Collect outcomes) |
| `collect` exits 4 `BLOCKED` although no entry carries a blocking finding or an open question | An entry returned `MERGE WITH FIXES` or `DO NOT MERGE` with only Minor / HARDENING-SUGGESTION findings — schema-valid, but not agreement (R-AGREE); its line in the collection report carries the deviation | Record the deviation. Neither a leader refutation nor an owner exception turns it into approval; a merge over it is an owner EXCEPTION, recorded as such (`references/triage.md` § Dispositions). Family coverage never decides the outcome |
| `collect` reports a wrapper entry INVALID: `the leg ran with a command other than the recorded one` (`no run-log under <attempt>/logs/<cli>/runs` or `the run-log … records an executed command that is not … dispatch.json's argv`) | The printed wrapper line was edited before it ran (a launch switch, the model, the tier, any token) or run without its `env TRIAD_REVIEW_LOG_DIR=…` member. The wrapper's run-log in the attempt's own namespace is the receipt of the executed argv, and `collect` admits an answer only when it equals the recorded `dispatch.json` argv (R-BIND) | `retry` the entry with a diagnosis and run its printed line VERBATIM, env included (`references/leg-contracts.md` § v2 dispatch shapes). The line shows the answer the leg gave beside the reason; it does not count. A receipt that "cannot be read" (unreadable or unparseable) or a recorded command that is unknown (the attempt's `dispatch.json` cannot be read) takes the same retry while the attempt is unsealed; once sealed, a run-log the seal cannot read is an integrity failure and the remedy is a new round |
| `collect` reports `integrity failure: … its run log <attempt>/logs/<cli>/runs changed` (or `was removed`) | A run-log file was added, changed or removed after the collection sealed the attempt — a second run of the line into a recorded attempt, or a hand edit | The sealed attempt does not count, and `retry` refuses it (a next attempt would sit behind the broken seal): a new answer needs a new round |
| The native `admit:` line exits 64 `--expected-<field> disagrees with <attempt>/binding.json` | A `--expected-*` flag was typed onto the printed admit line and disagrees with the attempt's own record | Run the printed admit line unedited — it takes the six values from `binding.json` and types none. Nothing was sealed or admitted by the refused run |
| A re-run into a recorded attempt is refused — the wrapper line or the native `guard:` line exits nonzero before the program starts, or `admit:` exits 64 `--admitted-out: the attempt directory is sealed` | The attempt is SEALED (R-BIND): its native admission (of an admitted reply), the first `collect` that judged it or `retry` recorded the answer, and a recorded attempt is never re-answered | A new answer needs `retry` after a failure to run (an attempt sealed INVALID, or `failed-to-run`, stays retryable; one sealed valid is refused) or a NEW round (SKILL rule 13). A `collect` reason ending `integrity failure: … — prepare a new round` means a sealed file changed, was removed or was replaced after the record — `earlier attempt K: integrity failure …` names a late write into an attempt `retry` replaced: that entry is `INCOMPLETE`, `retry` refuses it, and the remedy the reason names is a new round |
| The claude `admit:` line exits 1, 2 or 3 and `collect` then reports the claude entry `MISSING — no result file at <attempt>/admitted.json` | The admission REFUSED the saved reply. A refused reply is not sealed: the attempt holds no admitted result, so it collects as not admitted (never `never admitted — run the printed admit: line`, which is only for a reply the admission would admit) | Diagnose why the reply was refused, then `retry` the entry: it seals the attempt `invalid` over the `raw.json` it judged and allocates the next one (R-RETRY) |
| `collect` reports an entry INVALID `` `retry` recorded this attempt as failed to run (its next attempt was not recorded) `` | `retry` sealed the attempt it replaces and then stopped before the next attempt was recorded (an allocation that failed, a stop) | `retry` the entry again when no attempt K+1 is on disk: it allocates it. An attempt K+1 already on disk (an interrupted retry) refuses `retry` — prepare a new round (the `already exists` row below); `collect` names that refusal and its remedy, with the recorded attempt's state beside it |
| `retry` refuses `attempt K changed while retry judged it (a leg still running wrote into it) — nothing was sealed or allocated; collect again` | The leg was still running: it wrote into attempt K between `retry`'s judgement and its seal, so `retry` seals only bytes it judged | Do not retry: `collect` judges what attempt K now holds (a valid answer is completed work); retry only if that collection reports it failed to run |
| `collect` exits 2 `roster entry '<name>' changed while this collection ran: earlier attempt K: integrity failure …` | A leg still running wrote into an attempt `retry` replaced after this collection's first check; `collect` re-checks those attempts right before it writes an AGREED record, and nothing was recorded | The late write is that entry's integrity failure: the next `collect` reports it `INCOMPLETE`, and the remedy it names is a new round. A write after that last check is a known limit: while a retried leg may still be running, collect once more before using an AGREED |
