# agy terminal (65) causes — what the leader surfaces

Each of these is already matched at the wrapper layer, so none of them routes to
the repair agent (Hard rule 4): only `unknown` / `extraction-error` do.

| cause | what to tell the user |
|---|---|
| `cli-subscription-cap` | quota — daily reset, or re-dispatch later |
| `token-limit` | prompt size too large — shrink the prompt |
| `oauth-env` | STOP — re-login required through the CLI's own browser flow; no retry, no other route, the credential store is never read; auth stays user-managed |
| `config-conflict` | one of these: a `--web` dispatch whose web-evidence clause cannot be rendered from the vendored spec (`the web-evidence clause library prompts_v2.py is missing` or `the web-evidence clause cannot be rendered from <path>` — no vendor process runs, not even the version probe; remediation: reinstall the plugin, then re-dispatch); `agy --version` probed below `_STREAM_JSON_FLOOR` (1.1.8) or unprobeable, where the wrapper fails CLOSED before any vendor dispatch (remediation: `agy update`, then re-dispatch); a `--model` / `--effort` pin on agy below `_MODEL_FLAG_FLOOR` (1.1.10, where agy silently ignored both flags), also refused before any vendor dispatch (remediation: `agy update`, or drop the pin); a `--sandbox read-only` dispatch on agy below `AGY_V2_FLOOR` (1.1.18 — `the read-only path needs agy >= 1.1.18`), refused before any vendor dispatch (remediation: `agy update`); a read-only dispatch whose allowlist agent definition is missing or differs from the wrapper's embedded body (`agy agent definition <path> is missing or differs from the embedded body`), refused before any vendor dispatch (remediation: re-run the wrapper's `--setup-agents` host step once on this host — the command in SKILL.md Step 1, Host setup; when two wrapper builds share the agents directory, align their versions instead); agy refused the pinned `--model` / `--effort` pair (its stderr says the model `is not recognized as a known model or custom model in settings`, or `--effort is not supported for model` — measured once, for a model agy no longer lists, so the first remedy is another model agy lists (`agy models`); `--effort` dropped is the remedy only for a listed model that refuses it, a case no run shows yet; the run-log records `requested_model`); or the run's exposed runtime model (`init.model`) contradicts the pinned `--model` — the answer is withheld and the stderr line names both. For the last two the user changes the roster entry (or `--model`) — a new round on the review path, never a retry — and the leader never substitutes a model |
| `admission-refused` | the v2 admission census found a tool OUTSIDE the agent's allowlist in the stream (the allowlist class only; other refusals stay `vendor-error`); the complete answer is quarantined in the run-log. Driver-emitted, never a classifier patch — surface, one retry at most. |
| `vendor-timeout` | the stream's terminal `result` is `status: ERROR` with the typed `error` "timeout waiting for response" and an empty response — agy's own turn budget ran out. Driver-emitted (`_is_vendor_turn_timeout`), never a classifier patch; surface, one narrower re-dispatch at most. |
| `vendor-error` | the stream's terminal `result` event carried a non-empty answer WITH rc≠0 or a non-`SUCCESS` status. The answer is deliberately NOT on stdout: it survives only in the run-log's quarantined `extraction_error` copy and the raw NDJSON stream, which the leader does not open (Hard rule 2). Surface the classification token + exit codes and name the run-log path; a human can read it out of band to decide re-dispatch vs accept |

`config-conflict`'s floor gate is a deterministic pre-dispatch check and
`vendor-error` is driver-emitted on the answer-present path — neither is
something a classifier patch could express, which is why they stay out of the
repair branch.
